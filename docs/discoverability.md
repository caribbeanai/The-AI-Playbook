# Discoverability and publishing notes

## Repository discovery

The public repository is [caribbeanai/The-AI-Playbook](https://github.com/caribbeanai/The-AI-Playbook). Its descriptive README, linked government catalogue, topic-relevant headings and verified attribution make the content understandable to people and search tools. GitHub's About description, topics and website field complement that content.

Suggested topics: artificial-intelligence, caribbean, latin-america, caricom, government, public-sector, ai-governance, responsible-ai, use-cases, digital-government, small-island-developing-states, ai-playbook.

The website link used in this edition is the verified Playbook deployment, [aiplaybooklac.netlify.app](https://aiplaybooklac.netlify.app/). A custom domain should replace it only after ownership, routing and canonical behaviour are verified. The separate maestrosai signup landing should not be silently substituted for the Playbook's content site.

## What the files cannot do

A robots.txt file in a GitHub repository does not control github.com's crawler policy. A sitemap committed to a repository does not deploy a site or submit it to search engines. An llms.txt file is a descriptive resource; no crawler is required to use it, and it cannot guarantee inclusion, attribution or ranking.

This repository's earlier robots and sitemap files referenced a GitHub Pages URL even though Pages was not enabled when checked. This change does not enable Pages or claim a live Pages site. The revised robots file and removal of the stale sitemap avoid advertising an unverified deployment. If a rendered site is deliberately published later, configure its real canonical URL, actual routes, sitemap and crawler rules at that host, then verify live responses.

## Maintainer verification checklist

- Confirm public visibility remains intentional; never change access solely for SEO.
- Check the About description, topics and homepage against actual content.
- Verify README, author and association links and the current website's redirects.
- On a rendered website, check page titles, descriptions, canonical URLs, accessible headings and internal links.
- Verify robots and sitemap responses on the deployed host; avoid stale or nonexistent URLs.
- If using a custom domain, verify DNS, TLS, redirects and webmaster ownership before submitting a sitemap through the appropriate account.
- Recheck indexing directly through available search/webmaster tools. Discovery is controlled by search providers and cannot be guaranteed.
