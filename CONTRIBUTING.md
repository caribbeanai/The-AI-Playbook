# Contributing

Contribute corrections, jurisdiction-specific adaptations and tested implementation lessons through an issue or pull request. Keep examples public, synthetic or appropriately anonymised and authorised for public release. Removing names alone is not anonymisation in a small community.

## A useful submission

1. State the country or territory, institution type and service problem.
2. Select a readiness level and describe the non-AI baseline.
3. Include value, data, process, tools, sample output, risks, controls, metrics, dependencies and complexity.
4. Label the maturity claim accurately: proposed pattern, digital service, announced project, evaluated pilot or production deployment.
5. Cite official primary sources for laws, programmes and outcome claims, with dates and limitations.
6. Explain human authority, correction/appeal routes, accessibility, language, low-bandwidth and manual fallback requirements.
7. Do not include credentials, personal records, private client information, government security details or material you lack rights to publish.

Keep descriptions vendor-neutral. Do not promise ROI or search-engine rankings. Do not claim a pilot succeeded without an evaluation. Never insert unverified biography, awards, superlatives or endorsements.

## Validation

Run `python3 scripts/validate_content.py` before proposing changes. It checks catalogue counts, required fields, readiness levels, duplicate IDs, corresponding Markdown cards and local Markdown links. It does not establish legal compliance, factual correctness, external URL availability or rendered accessibility; those require review.

The current repository is Markdown/JSON documentation. There is no application build or enabled GitHub Pages deployment in this change. Preserve the existing MIT licence and notices; third-party sources have their own terms.
